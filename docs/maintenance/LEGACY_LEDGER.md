## Method and scope

This ledger records what the current repository proves, not what historical names imply. The audit
covered `apps/`, `packages/`, `games/`, `game-registry/`, `examples/`, `scripts/`, `e2e/`,
`.github/workflows/`, `docs/`, workspace/build configuration, Wrangler configuration, all D1
migrations, deployment bootstrap, tests, fixtures, and generated artifacts.

For each candidate, static imports and exports were followed into composition roots, routes,
generators, package scripts, CI/deploy workflows, persistence adapters, migration triggers, tests,
and documentation. A generated file or test-only reference is not treated as dead without checking
whether it is a build invariant or regression guard.

Production game resolution at this base is provider-neutral:

```text
D1 games/game_versions/game_assets
+ B2 game-definitions/<slug>/definition.json and games/<gameId>/<versionId>/...
-> ComposedRuntimeGameRegistry -> /play/:slug and /games/:gameId/:versionId/*
```

The classifications below describe cleanup eligibility only. They do not authorize deletion,
migration, deployment, or persistence changes.

## Proof boundary for `DELETE` candidates

The five `DELETE` rows were checked beyond import counts:

1. Removed-runtime references have no implementation, route, loader, workflow, storage, or
   migration consumer. The architecture-token occurrences are retained separately as required
   negative guards.
2. Old official path/release-map prose conflicts with the current API route table, generic object
   keys, deploy bootstrap, 404 regression test, and workflow guard. No old writer or serving route
   remains.
3. The two Web dev helpers are app-local and have no callers; removing them does not remove their
   independently classified server APIs.
4. The core compatibility barrel duplicates the already-exported real port module, has no direct
   import, and cannot be imported as a package subpath under the package export map.
5. The R2 adapter has no export, binding, construction, test, build/deploy hook, or persistence
   object to preserve; B2 is the configured implementation.

These facts establish cleanup eligibility, not permission to remove them during F-0.

## Documentation drift and next stage

**Recommended next stage: F-1 Documentation Foundation.**

Although five low-to-medium-risk deletion units are proven, documentation drift materially
obstructs safe cleanup:

- `README.md` and several guides link `docs/ADMIN_GUIDE.md`, but that file does not exist.
- `docs/ARCHITECTURE.md` links nonexistent `docs/runbooks/*` and `docs/archive/*` files and still
  describes dynamic Web game loading as the plugin path.
- `docs/DATABASE.md` says only migrations `0000-0031` exist and describes migration 0025 as
  branch-only, while `main` contains and deploys through 0033.
- `docs/GAME_CREATION_GUIDE.md` describes removed Game Creator/System runtime selection and old
  `/official-games` storage/serving/release-map behavior.
- `docs/AUTHORIZATION.md` says `canApplyForGameCreator()` is always `true`; current code and tests
  require `false`.
- No `docs:check`, documentation index, or link checker exists in `package.json`.

F-1 should establish an indexed authoritative documentation set, repair broken links, update the
database and game creation/upload guides to the current generic platform, and add a lightweight
link/drift check. The five `DELETE` units can then form an independent F-2; none of the five
`MIGRATE_THEN_DELETE` rows belongs in that purge.

## Unresolved risks and deferrals

- Do not remove or rewrite applied D1 migrations. Trigger removal requires a new migration plus
  proof that old Worker writes and rollback gaps have closed.
- Do not collapse USER review state into generic publication state: `READY != APPROVED`.
- Do not remove raw-session or admin-login compatibility without production cutover evidence.
- Do not infer OWOGG authority from slug, Game Creator/display name, or old SYSTEM labels.
- Preserve iframe sandboxing, signed one-use attempts, canonical policy validation, and
  primary-authority reads for correctness-sensitive operations.
- Manual examples/fixtures need a maintainer support decision; absence from CI alone is not proof
  that humans do not use them.
- Interactive official-admin publication remains blocked on an explicit authority/precedence
  decision.
